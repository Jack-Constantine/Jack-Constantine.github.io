CHAPTER 01

写下第一行 TypeScript

先写出一条能运行的语句，再认识这一行里的点、括号、引号和分号。

  1. console 是运行环境已经提供的一个对象，可以先把它理解为一组和控制台有关的工具。
  2. 点 . 用来取出对象上的成员。console.log 取出负责打印的函数。
  3. (...) 调用这个函数，括号里是交给它的内容。"你好，TypeScript！" 是一个字符串，引号标记文字的起止位置。
  4. 分号 ; 在这里结束这条语句。入门示例统一写上分号。语法符号使用半角字符，字符串里的文字可以使用中文标点。

CHAPTER 03

写条件，让程序选择一条路

区分赋值和比较，读懂括号中的条件和花括号中的语句。

if (条件) { ... } 中，圆括号包住要判断的表达式，花括号包住满足条件时执行的语句。这里先检查 72 >= 90，得到 false。继续检查 72 >= 60，得到 true，于是打印「通过」。这一组分支只执行其中一块。最后一行在花括号外，所以无论选中哪条分支，都会打印「评估结束」。

= 写入值，=== 比较是否相等，!== 比较是否不等。&& 用来组合「两个条件都成立」，|| 表示「至少一个条件成立」，! 反转一个条件。刚开始可以用括号明确每个子条件的边界。

自测 · 把第一段的 score 改为 90，会输出什么？

先输出「优秀」，再输出「评估结束」。第一条条件已经成立，后面的 else if 不再进入。

CHAPTER 04

用数组装多个值，再逐个处理

认识方括号的两种写法，学会用循环完成一次累计。

string[] 在类型位置读作「字符串数组」。等号右边的 ["读资料", "写笔记"] 创建一个数组。变量后面的 [0] 是索引，取第一项。.push(...) 调用数组的方法追加一项，.length 读取长度，所以后面没有圆括号。const tasks 固定这个名字所指向的数组，仍可以往数组里加元素。

for (const cost of costs) 读作「从 costs 中依次取一个值，这一次叫它 cost」。花括号内的代码重复执行。total 放在循环外，只初始化一次。第一轮算 0 + 2，第二轮接着算 2 + 4，第三轮算 6 + 3。若把 let total = 0; 挪进循环，每轮都会从零重新开始。

需要索引时，用三段式 for

圆括号里的三个部分用分号隔开。let i = 0 只执行一次。每轮开始前检查 i < tasks.length。如果条件成立，执行花括号里的代码，再执行 i = i + 1，回到条件检查。索引从零开始，给人看的编号用 i + 1。

只要条件成立就重复，用 while

while 在每一轮前判断条件。这里每轮都减少 remaining，到零时退出。循环里遇到 break 会立即离开循环，遇到 continue 会跳过当前轮余下的语句。写 while 时留意每条分支是否都能让循环最终结束。

CHAPTER 05

写一个函数，给它参数并接住返回值

把声明和调用分开看，再识别项目里常见的箭头写法。

  1. function add 定义一个名叫 add 的函数。程序随后遇到 add(2, 3) 才会执行函数体。
  2. (a: number, b: number) 声明两个参数及各自的类型。调用 add(2, 3) 时，a 得到 2，b 得到 3。
  3. 右括号后的 : number 是返回类型。return a + b; 结束本次调用，把计算结果交回调用处。
  4. const sum = add(2, 3); 把返回的值保存到 sum。下面的 console.log(sum) 才把它显示出来。

箭头函数的两种函数体

=> 左边是参数，右边是函数体。只有一个表达式时，它的结果自动返回。右边若是花括号语句块，需要用 return 交回结果。第 11 章会进一步讲回调和闭包，初学时先练习从调用找到函数定义，再顺着 return 找到返回值。

自测 · console.log(add(3, add(1, 2))); 会输出什么？

输出 6。先执行内层的 add(1, 2)，得到 3；外层实际执行 add(3, 3)。

CHAPTER 06

用对象把相关值放在一起

从属性读写过渡到对象类型，然后串起前六章的写法。

等号右侧的 { ... } 创建一个对象。title: "整理笔记" 是一个属性，冒号左边是键，右边是值。属性用逗号分隔。task.title 读取 title，task.done = true; 修改 done。这里的花括号是在表达式中构造值，条件或函数中的花括号则包住一组语句。

把对象的形状写成类型

  1. type Task = { ... } 给一份类型起名字，描述有哪些属性、每个属性接受什么样的值。这里的 title: string 写的是字段类型。
  2. describe(task: Task) 的参数需要符合这份类型。函数先看 done，再返回一条文字。命中第一个 return 时，函数立即结束。
  3. Task[] 表示数组中每一项都是符合 Task 形状的对象。循环把它们逐个交给 describe，再打印返回值。

CHAPTER 07

一份代码，两条时间线

看懂 .ts 文件怎样变成可执行行为，以及为什么类型正确和程序正常是两回事。

这里有两个变化。Python 的类型注解通常交给额外工具检查，Python 的字符串可以乘整数做重复。TypeScript 检查器会拒绝第二次调用；一旦对应 JavaScript 真的运行，JS 的 * 会把数字字符串转成数值。静态诊断与运算符语义各有自己的规则。

实验 · 同一函数经过类型擦除

type Count = number; const count: Count = 4; console.log(count * 2);

运行产物会打印 8。上图的②可以发现错误；noEmitOnError 决定发现错误时是否停止输出新产物。

把浏览器和 Node.js 理解成两种宿主。浏览器提供 DOM，Node 提供文件系统和进程 API。两者都能执行 JavaScript，所提供的 API 不同。TypeScript 的类型注解和 .d.ts 声明可描述这些 API，实际实现由宿主或依赖提供。

回到第一章的运行命令

第 01 章用 node hello.ts 直接启动代码。Node.js 24 可以擦除该示例的类型语法，再运行留下的 JavaScript。这条路径主要用于观察执行行为。到第 21 章再安装 tsc，把类型检查、生成文件和执行产物接起来。

深入一层 · Node 开始执行后发生什么？

加载器解析入口与依赖。对 ESM 来说，静态导入关系会在模块求值前建立。Node 使用的 V8 引擎解析 JavaScript、执行代码，并可根据运行反馈优化热点代码。函数调用创建执行上下文，调用结束后相应的栈帧退出。数组和对象通常通过引用共享，闭包引用的值也可在调用返回后继续存活。垃圾回收器根据可达性回收内存，所以函数返回并不意味着它创建的每个对象都会立刻消失。

例如第 11 章的 counter() 返回一个函数。只要返回的函数还可达，它引用的计数状态就能继续被读写。到了第 18 章，await 挂起后，恢复执行所需的状态也会跨调度保留。这里用调用栈和引用关系理解程序行为，V8 的实际存储位置可能受优化影响。

自测 · 能否用类型决定运行时分支？

类型别名 type Count = number 在产物里消失，无法写 x instanceof Count。可以执行 typeof x === "number"，因为 typeof 读取的是运行时值。

CHAPTER 09

控制流、比较与空值

用代码看清真假、相等、默认值以及循环的边界。

条件使用 if (条件) { ... } else if (...) { ... } else { ... }。常见 falsy 值有 false、0、0n、""、NaN、null、undefined。判空数组用 items.length === 0，判空对象可用 Object.keys(obj).length === 0 检查可枚举的自有字符串键。=== 不做跨类型强制转换，对象则按身份比较。== 有转换规则，阅读时留意 x == null 常被用来同时匹配 null 与 undefined。

  • a || b 在 a 为 falsy 时求值 b。a && b 在 a 为 truthy 时求值 b。它们返回操作数。
  • a ?? b 在 a 是 null 或 undefined 时求值 b。
  • a?.b、a?.[key]、fn?.() 分别对左侧的对象或函数进行空值短路。对多层可空属性逐层写 user?.profile?.name。
  • 默认参数、解构默认值只在值是 undefined 时启用。允许传入 null 时，它会原样保留。

for...of 迭代可迭代值。for...in 遍历对象可枚举的字符串属性名，可能包含原型上的属性；普通对象的自有键值对用 Object.entries(obj)。switch 匹配后会继续执行后续分支，除非遇到 break、return 或 throw。

自测 · 要保留重试次数 0，该选哪个运算符？

选 retries ?? 3。分别代入 0、undefined 和 null，结果是 0、3 和 3。

CHAPTER 10

数组、对象、Map 与解构

用 Python 列表推导式和字典经验，迁移到常见的数据处理链。

map 逐项变换，filter 按条件保留，find 返回第一个命中值或 undefined，some 判断是否存在。聚合时可写 nums.reduce((sum, n) => sum + n, 0)，最后的初始值让空数组也得到确定结果。用 sort((a, b) => a - b) 做数值排序，默认排序按字符串比较。sort 会修改数组，[...nums].sort(...) 先复制外层。

对象展开的同名键由后写的属性覆盖。对象展开与数组展开都是浅复制。这里 settings.nested 和 defaults.nested 持有同一个对象。{ name: label } 的冒号表示把属性 name 绑定到局部变量 label。

要表达的数据常见写法读代码时要注意
同类元素序列string[] / Array<string>越界索引给出 undefined。默认的 strict 未启用 noUncheckedIndexedAccess。
固定位置和含义[string, number]元组在运行时仍是数组。可以用 readonly [string, number] 限制通过该引用修改。
按键查值Record<string, number> 或 Map<string, number>前者描述普通对象的类型，后者是运行时容器，能用对象作键，get 将缺失建模为 undefined。

常见陷阱是用 Record<string, Value> 后把任意键都当成存在。有限集合用 Record<"read" | "write", Value> 强制填齐已知键，动态查找可以用 Map.get、显式 Value | undefined 或开启索引访问检查。

CHAPTER 11

函数、回调、闭包与 this

从 def、lambda 和闭包出发，读懂 TS 项目里大量出现的箭头函数与函数类型。

函数名后的一对括号是参数，最后一个冒号后的 string 是返回类型。这里第二个参数先用 = {} 处理整个参数缺失，再用 prefix = "job" 处理对象属性缺失。n?: number 允许省略参数，函数体中 n 可能为 undefined。...args: string[] 把剩余位置参数收成数组，调用侧的 fn(...args) 把数组展开成实参。

(value: string) => string 在类型位置描述调用形状。value => value.toUpperCase() 在值位置创建函数，并借助上下文推断参数类型。箭头函数的表达式体自动返回结果，花括号块体需要 return。返回对象字面量时用 ({ value }) 包起来。

两次调用 counter 创建独立的局部作用域。返回的函数仍引用各自的 n，因此能跨调用积累状态。普通函数和方法的 this 取决于调用方式。执行 obj.run() 时接收者是 obj，取出 const run = obj.run 后直接调用会丢失接收者。箭头函数从定义处捕获 this。

CHAPTER 12

对象形状、接口与类

分清形状约束、实例身份和可变状态。

只要变量的形状满足接口，它就可以传给 describe。可以把这想成由检查器提前确认的鸭子类型。直接传入新鲜对象字面量时，额外的属性检查常用于捕捉拼写错误。readonly 限制通过这个类型视图写入，约束不会递归，也不会冻结 JS 对象。Object.freeze 会在运行时冻结对象的外层。

retries?: number 表示属性可缺失，读取时可能得到 undefined。retries: number | undefined 要求键存在，值可为 undefined。开启 exactOptionalPropertyTypes 后，若希望可选属性还允许显式写入 undefined，要把它写进属性的值类型。

interface 可用 extends 扩展对象形状，同名接口在适用作用域可合并。type 还可为联合、元组、原始类型及类型计算起别名。A & B 表示同一个值要同时满足两种约束，遇到同名字段类型冲突可能得到 never。运行时合并对象由 {...a, ...b} 完成。

class 同时有类型和运行时值两面。new Counter(...) 产生对象，instanceof Counter 检查该构造函数的原型是否出现在对象的原型链上。implements 用于静态检查，接口不进入原型链。TS 的 private 主要由类型检查器约束，JS 的 #n 有运行时私有语义。读到 constructor(public name: string) {} 时，public 参数属性是 TS 简写，会在实例上创建并初始化属性。

类的普通方法由实例通过原型链找到，实例字段属于每个实例。extends Base 建立继承关系，派生构造器在使用 this 之前调用 super(...)。static 成员从类本身访问。abstract 声明由派生类完成的契约。

CHAPTER 13

联合、收窄与穷尽检查

联合类型让状态差异进入类型系统，再用真实分支把类型范围缩小。

联合 A | B 代表值可能属于任一成员。检查器只允许无条件访问所有成员共同支持的操作。typeof、instanceof、字面量比较、in 和 Array.isArray 都能提供收窄线索。记得 typeof null === "object"，要处理可空对象时先显式排除 null。

never 表示在当前静态分析里没有可达的值，也可作为总会抛异常的函数返回类型。新增 { kind: "cancelled" } 后，若忘记补 case，默认分支仍可能收到 cancelled，便会在传给 unreachable 时得到编译诊断。用 kind、type 或 status 区分请求结果、事件、命令和状态，是阅读 TS 项目时值得优先识别的结构。

普通对象的属性可被重新赋值，初始化时的 "read" 常被拓宽成 string。satisfies Job 检查表达式满足目标约束，并保留表达式自己的推断结果。as const 让字面量保留精确值，将对象字面量属性标为只读，并把数组字面量推断为只读元组。两者在运行时都被擦除。

自测 · 为什么 if (value) 可能把合法输入排除？

如果 value 的类型是 number | undefined，0 是合法数值但在真假判断中为假。用 value !== undefined 表达检查的真实目的。

CHAPTER 14

泛型保留输入与输出的关系

把 T 看成由调用决定的类型参数。像 Python 的 TypeVar 一样，重点在各个位置的类型如何关联。

first<T> 宣告了类型参数。readonly T[] 允许传入可变或只读数组，函数体只能通过这个引用读取。T | undefined 表达空数组的运行结果。若改成 any[] → any，调用后就失去了元素类型的线索。

这里的 extends 表示类型约束。第一步推断 T = { name: string; retries: number }，第二步得到 keyof T = "name" | "retries"，第三步用传入的键决定 K，最后 T[K] 读出对应属性的类型。keyof 计算类型层的键，Object.keys 才会枚举某个实际对象的键。

E = string 给类型参数默认值。只传 Outcome<number> 时错误载荷为字符串，也可以在另一个接口里写 Outcome<User, Error>。泛型从实参推断或由调用方提供，执行函数时没有一个名叫 T 的运行时参数。想按类别构造实例时，需要传构造函数或工厂等运行时值。

CHAPTER 15

类型变换与推断

顺着符号从里向外读，弄懂项目里常见的 keyof、typeof、映射类型与 infer。

  1. typeof actions 在类型位置获取变量的静态类型，这里是 readonly ["read", "write"]。表达式里的 typeof actions 则在运行时得到 "object"。
  2. [number] 获取数字索引可读出的元素类型，即 "read" | "write"。
  3. Record<Action, Handler> 要求每个动作名对应一个函数。添加动作后缺少相应实现，检查器会指出。

CHAPTER 16

外部数据、断言与异常

给来自文件、命令行或网络的值安排明确的运行时检查。

JSON.parse 的库签名返回 any，这里主动接到 unknown，避免不可信值绕过检查。value is Job 告诉检查器：守卫为真时可以按 Job 读字段。守卫本身的判断由作者负责，漏掉 retries 的检查也可能照样编译。处理外部输入时可检查类型之外的业务约束，例如次数非负和路径非空。

语法影响阅读时的问题
any允许许多未检查的操作，结果还能继续传播为 any数据来自哪里，在哪里获得保证？
unknown可接收任意值，使用前要收窄检查覆盖了哪些字段或分支？
value as Job可接受的断言改变静态视图运行时是否有证据支持这一形状？
value!在类型上排除 null 和 undefined哪个前置条件保证了值存在？
String(value) / Number(value)运行时转换是否要拒绝 NaN、空字符串等特殊结果？

JS 可以抛出任何值，catch 里先用 instanceof Error 收窄，再取 message。finally 在成功、异常或提前返回时都会执行，适合释放资源。可预期且需要调用者分类处理的失败，也可显式返回第 14 章那样的 Outcome。

CHAPTER 17

import、export 与依赖解析

把 Python 的 import 经验迁移到 Node.js，同时建立 ESM 和 CommonJS 的概念。

右侧是两个文件。以第 21 章的 NodeNext 配置为例，TypeScript 检查 main.ts 时可用 ./task.js 找到 task.ts。编译产物保留 ./task.js，Node 运行时会找到真正的 dist/task.js。type Task 这一导入项被擦除。只有类型时可直接写 import type { Task } from "./task.js"。

看到的写法含义
import { run as execute } from "./task.js"命名导入并在当前文件改名。
import run from "./task.js"导入模块的默认导出，由 export default 对应提供。
import * as task from "./task.js"获得模块命名空间，通过 task.run 读导出。
export { run } from "./task.js"从当前入口重新导出。读 index.ts 时可能还要再跳一层。
import "./setup.js"为了执行模块顶层的初始化逻辑而导入。
const task = await import("./task.js")在执行到该表达式时动态加载，结果是模块命名空间的 Promise。
const task = require("./task.cjs")CommonJS 的典型加载写法，导出对象通常来自 module.exports。

ESM 的静态导入由宿主在模块求值前处理，导入绑定随导出绑定更新。依赖模块的顶层代码会参与求值，循环依赖时可能在绑定初始化前就被读取。package.json 里的 "type": "module" 让该包范围下的 .js 明确按 ESM 解释。.mjs 明确是 ESM，.cjs 明确是 CommonJS。编译时 .mts、.cts 可分别输出为两者。

以 import { readFile } from "node:fs/promises" 为例，node: 指向 Node 内置模块。"some-package" 这样的裸模块说明符通常交给包解析，包的 exports 能指定不同条件的公共入口。"./task.js" 则相对当前模块解析。paths 可以告诉 TS 检查器怎样查别名，运行时要由 Node 的包映射、打包器等机制提供对应解析。

两套问题要分别查。 TS2307 属于检查时的解析问题。ERR_MODULE_NOT_FOUND 来自 Node，先查产物路径、文件扩展名、依赖是否安装和包导出规则。

CHAPTER 18

Promise、async/await 与事件循环

学会预测输出顺序，理解等待 I/O 时函数和运行时分别在做什么。

调用 JS 的 async 函数会同步执行到首次挂起或完成，同时给调用者一个 Promise。return 7 让 Promise 兑现为 7。throw 让 Promise 拒绝。await 会暂停当前 async 函数后续的执行，即使等待的值已兑现，续段也会稍后调度。调用者和事件循环可以继续处理别的工作。示例中的 void main() 丢弃返回值，真实入口仍需处理可能的拒绝，例如 main().catch(report)。

同步函数通过调用栈执行。网络和文件 I/O 由宿主协调，完成后相关回调或 Promise 续段才有机会运行。同步的长循环仍会占用 JS 执行线程。setTimeout(fn, 0) 代表尽早调度，运行顺序还受当前任务和队列影响。

两个 delayed 在构造数组时就启动。Promise.all 兑现后的数组保持输入顺序，任一个拒绝会使组合 Promise 拒绝，其他操作仍会继续，除非另外取消。要收集成功与失败两类结果，用 Promise.allSettled。异步有先后依赖时按次序 await；独立操作可先发起再一起等待。需要逐项等待时用 for...of 加 await，forEach(async ...) 会丢弃回调返回的 Promise。

自测 · 两次 await 写在循环里，会发生什么？

若每次迭代先创建一个 Promise 再等待它，第二次操作要等第一次完成才启动。若循环前已把两项操作都启动，随后逐项等待只决定消费顺序。

CHAPTER 19

异步迭代、流式事件与取消

读懂一串分批到达的值，以及调用方如何通知底层操作停止。

和 Python 的异步生成器与 async for 类似，async function* 返回可异步迭代的生成器。每次请求下一项都会得到一个 Promise，兑现为迭代结果对象，形如 { value, done }。for await...of 替你等待、取值并判断结束。这里的业务事件 { kind: "done" } 和迭代器自身的 done: true 属于两层协议。提前 break 会在可用时调用并等待迭代器的 return()，生成器可在 finally 中清理资源。

CHAPTER 20

tsc、运行器与调试

从启动脚本追到真正执行的文件，区分检查、转译、打包和宿主执行。

设置 / 文件解决什么问题
package.json项目脚本、依赖、JS 模块类型和包元数据。package-lock.json 记录依赖解析结果。
strict打开一组严格检查，例如空值处理和隐式 any。noUncheckedIndexedAccess 与 exactOptionalPropertyTypes 是另行选择的检查。
